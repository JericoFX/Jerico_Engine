# JoltPhysics de iamjbq: reutilización futura para JericoEngine

Revisión estática del 16/10/2026, sin clonar, compilar, instalar ni integrar. **Tiene una base reutilizable, pero no equivale a una integración física completa ni verificada.** Todas las capacidades siguientes significan código presente o ausencia concreta, nunca PASS nativo.

## Identidad y compatibilidad

Se revisó la rama predeterminada initial-release, commit **6fd64c45b635b58e44365e304722aed859f62898**, del 01/10/2026: mejora de validación de mallas cocinadas. [Commit primario](https://github.com/iamjbq/JoltPhysics/commit/6fd64c45b635b58e44365e304722aed859f62898).

El manifiesto declara Gem **1.0.0**, autor/origen Jason Quinn, servicio exclusivo Physics, pero compatible_engines y engine_api_dependencies están vacíos: **no fija una versión O3DE compatible**. No confundir versión del Gem con versión del motor. [gem.json](https://github.com/iamjbq/JoltPhysics/blob/6fd64c45b635b58e44365e304722aed859f62898/gem.json).

CMake fija **Jolt v5.6.0**, cuyo tag oficial apunta al commit **e77f175595e64cb44218cc9d9d56fc365ad0e36a**; usa FetchContent. La compatibilidad objetivo es AzPhysics/PhysX y el README advierte desarrollo activo y posibles fallos de compilación. [CMake](https://github.com/iamjbq/JoltPhysics/blob/6fd64c45b635b58e44365e304722aed859f62898/Code/CMakeLists.txt), [tag oficial](https://github.com/jrouwe/JoltPhysics/tree/v5.6.0), [README](https://github.com/iamjbq/JoltPhysics/blob/6fd64c45b635b58e44365e304722aed859f62898/README.md).

## Reutilización nativa y dependencias

Candidatos de reutilización futura: conversiones AZ/Jolt, adaptación de cuerpos/shape y filtros, manejo de materiales físicos y camino SceneAPI→binario Jolt→asset. Eso permitiría aprovechar trabajo sin conservar el registro Gem. Es una valoración de piezas, **no decisión ni implementación de arquitectura**.

No copiar su composición sin revisión: módulos/aliases Gem, LmbrCentral, Legacy::CryCommon/Editor.Headers y CommonFeaturesAtom; incluso la API runtime depende públicamente de AzToolsFramework. El CMake descarga Jolt y VHACD automáticamente. JoltSystem usa allocator predeterminado y un JobSystemThreadPool de hardware_concurrency−1; el adaptador de jobs propio está comentado y Reinitialize no está soportado. No es todavía la política nativa/offline/de recursos de JE. [CMake](https://github.com/iamjbq/JoltPhysics/blob/6fd64c45b635b58e44365e304722aed859f62898/Code/CMakeLists.txt), [JoltSystem](https://github.com/iamjbq/JoltPhysics/blob/6fd64c45b635b58e44365e304722aed859f62898/Code/Source/System/JoltSystem.cpp).
