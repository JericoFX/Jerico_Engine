# Native ImGui integration — 2026-10-12

Scope: the existing ImGui implementation is owned by `Engine/Debug/ImGui`, with `JE::DebugImGui`, `JE::DearImGui` and adapted C++ under `JE::Debug`. Editor, Asset Processor, AssetBuilder and the launcher compose native module factories directly. The old ImGui Gem activation is removed from catalogs, seeds and consumers. Its historical CMake entry rejects reactivation. Atom retains its existing viewport contexts and rendering passes; this does not introduce another renderer or claim a single global context.

## Vulkan GPU profiler regression

Opening TimestampView crashed inside the driver. A live debugger captured a valid device/function pointer but the second timestamp domain was `1000208000`, with null `pNext`. The existing selection accepted any non-device domain as a CPU clock. New drivers can report PRESENT_STAGE_LOCAL_EXT, which requires additional swapchain data: [Khronos calibrated timestamp requirements](https://docs.vulkan.org/refpages/latest/refpages/source/VkCalibratedTimestampInfoKHR.html), VUID 12227.

`Device.cpp` now selects only the three known host clocks, preserves the RAW preference, resets the sentinel on initialization and avoids the driver call when there is no valid host clock. No SDK update, disabled profiler or fabricated timings. The focal Vulkan build exited 0 in 20.993 seconds; source SHA-256 `A6C6E2A75B1CFFD7E76492C793B4F8CB07334977D6F364AEDF41FD602D45F815`.

GREEN: the same Vulkan room now displays live per-pass durations and the GPU timeline without the access violation. Original screenshots are in `vulkan-attempt2`. DX12 TimestampView had already passed. The displayed ~1.98 ms Vulkan and ~2.47 ms DX12 values are single samples, not comparative performance measurements. The fixed host-domain numeric value was not recaptured under the debugger. The old pre-integration binary was not tested for this crash, so this is not attributed to the ImGui migration itself.
